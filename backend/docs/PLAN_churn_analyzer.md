# Анализатор рисков оттока: план работ (фронт и бэк)

Кейс Aeza, уровень Middle. Цель: панель для маркетолога, которая показывает, у кого из клиентов риск ухода, почему и сколько денег можно потерять.

Поля сверены с датасетом из кейса (папка `data/`: `data.json`, схема `source_schema.sql`, `generate.py`, README организаторов).

## Роли

- **Бэк-1:** доступ, инфраструктура, метрики, живое обновление, документы.
- **Бэк-2:** данные, модель риска, пересчёт, список клиентов.
- **Фронт:** панель (экраны ниже). Работает по контракту, пока бэк не готов, использует моки.

## Данные (data/data.json)

10 аккаунтов, 30 услуг, 100 транзакций. Снимок для `PUT /source/snapshot` имеет ту же форму, что `data.json`: объект с массивами `accounts`, `services`, `transactions`, поля в camelCase. Жюри может прислать свой снимок большего объёма, поэтому загрузка должна быть устойчивой (валидация, понятные 422, замена в одной транзакции).

- **accounts:** `id`, `email`, `balance`, `withdrawBalance`, `totalReplenished`, `bonusBalance`, `bonusState` (`locked` или `unlocked`).
- **services:** `id`, `name`, `ownerId`, `paymentTerm` (`hour`, `week`, `month`, `quarter_year`, `half_year`, `year`), `autoProlong`, `createdAt`, `expiresAt`, `status` (`active`, `blocked`, `deleted`, `suspended`, `prolong_wait`), `price`.
- **transactions:** `id`, `amount` (0..1000), `status` (`performed` или `not_performed`), `performedAt` (или `null`), `createdAt`, `type` (`prolong` или `order`), `serviceId`.
- Все суммы в евроценты (1 евро = 100). У транзакции нет аккаунта: связь через `serviceId` -> `services.ownerId`.

Что заметно в данных:
- В PDF поле называется `autoprolong`, в данных `autoProlong`. Ориентируемся на данные.
- Данные синтетические: у каждого аккаунта три услуги и все в одном статусе (статус зависит от номера аккаунта). Для демо нужен расширенный и более разнообразный набор: `generate.py` умеет `--accounts 100 --services 300 --transactions 1000 --seed 42`, но статусы в нём тоже идут по кругу, при необходимости доработать генератор.
- Цены 1..960, балансы от 3478: простое «баланс меньше цены» почти не срабатывает. Лучше считать запас в днях: баланс (плюс бонусный, если `unlocked`) делить на суточную стоимость услуг (час = цена × 24, неделя = цена / 7, месяц = / 30, квартал = / 91, полугодие = / 182, год = / 365).
- Опорная дата данных 2026-10-19T15:00Z, статусы со временем не меняются. Если считать от «сейчас», часовые `active` услуги покажутся давно истёкшими. Нужна настройка `asOf` (пусто = сейчас, или фиксированная дата, например дата снимка).
- `prolong_wait` в данных бывает с давно прошедшим `expiresAt`, хотя по правилам через 5 дней он должен стать `deleted`. Опираться на статус, а не только на дату.
- Дат удаления нет: для графика «исторических удалений» брать `expiresAt` услуг со статусом `deleted` как приближение.
- `amount` не связан с `price`; в score использовать только долю неуспешных транзакций, не суммы.

## Общий контракт API

Префикс `/api/v1`, пути без слэша на конце, JSON в camelCase. Деньги в ответах в евроцентах (целые), фронт делит на 100. Уровни: `high`, `medium`, `low`, `no_data`.

- `POST /auth/login`, `GET /auth/me`, `POST /auth/logout` — вход по логину и паролю, сессия в httpOnly cookie.
- `GET /customers?level=&search=&sort=&order=&page=&pageSize=` — список: `id`, `email`, `balance`, `totalReplenished`, `riskScore` (число или null), `level`, `reasonShort`. Сортировка по `id`, `email`, `balance`, `totalReplenished`, `riskScore`, `order=asc|desc`.
- `GET /customers/{id}` — карточка: `balance`, `bonusBalance`, `withdrawBalance`, `bonusState`, `riskScore`, `level`, `factors[]` (`code`, `name`, `weight`, `contribution`, `explanation`), `services[]` (`id`, `name`, `status`, `price`, `autoProlong`, `paymentTerm`, `expiresAt`, `risk`), `expectedLossCents`.
- `GET /analytics/summary` — `customersTotal`, `byLevel` (`high`, `medium`, `low`, `noData`), `expectedLossCents`, `servicesAtRisk`, `asOf`, `updatedAt`.
- `GET /model/settings`, `PATCH /model/settings` — `weights` (по коду признака), `thresholds` (`medium`, `high`), `horizonDays`, `asOf` (null = сейчас). PATCH запускает пересчёт.
- `PUT /source/snapshot` — тело как `data.json`, полная замена данных и пересчёт; ответ: число записей и `recalculatedAt`.
- `GET /events` — SSE-поток, событие `recalculated` после любого пересчёта.
- `GET /metrics` — Prometheus: клиенты по уровням, ожидаемые потери (числа те же, что в панели).
- `GET /docs` (Swagger) и файл `openapi.json` в репозитории.
