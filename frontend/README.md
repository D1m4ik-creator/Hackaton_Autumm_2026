# Aéza — frontend

React, TypeScript, Vite, Ant Design и Zustand.

## Запуск

```powershell
npm.cmd install
npm.cmd run dev
```

Приложение: **http://127.0.0.1:5173**. Требуется запущенный бэкенд.

## Подключение к API

Фронтенд ходит на API с общим префиксом `/api/v1`. По умолчанию — на тот же
origin, что и открытая страница (в Docker nginx проксирует `/api/` и `/metrics`
на сервис `api`). Для dev-сервера vite нужен явный адрес бэкенда в `.env`,
с тем же хостом, на котором открыт фронтенд:
например, `VITE_API_URL=http://127.0.0.1:8000` для `http://127.0.0.1:5173`.
Cookie сессии передаются в HTTP-запросах и SSE. При 401 выполняется общий
refresh с повтором запроса; при подтверждённом истечении сессии открывается вход.
Сетевая ошибка, 429 или 5xx при refresh сохраняют пользователя и черновики:
после восстановления сервера операцию можно повторить.

После входа доступны `/` (сводка), `/app/clients` и `/app/clients/:id`.
Таблица использует серверные поиск, фильтр уровня, сортировку и пагинацию.
Поля сортировки: `id`, `email`, `balance`, `totalReplenished`, `riskScore`;
направления: `asc` и `desc`. Все денежные значения API — евроценты.
Выбранный уровень риска, поиск и сортировка сохраняются при переходах между
страницами приложения, включая дашборд и карточку клиента.
`no_data` и `riskScore: null` отображаются как «нет оценки».
На дашборде видны объяснение потерь `lossExplanation` и дата исходных данных
`asOf`; в таблице — score, уровень и короткая причина риска.
Пункт «Метрики /metrics» открывает `/metrics` бэкенда в новой вкладке
(тот же origin, без префикса `/api/v1`).

Поток `/api/v1/events` с cookie обновляет сводку, текущую страницу клиентов,
приоритетных клиентов и открытую карточку по событию `recalculated`.
Закрытие SSE с истёкшим токеном вызывает refresh и новое подключение;
первое `ready` и смена версии при восстановлении соединения также обновляют
данные, включая пересчёты между первоначальным GET и подключением SSE.

Администратору доступны `/app/model-settings` (GET/PATCH конфигурации),
`/app/users` (создание, изменение и удаление менеджеров) и загрузка JSON-снимка
через `PUT /api/v1/source/snapshot`. После загрузки показаны количества аккаунтов,
услуг и транзакций. Ошибки в файле указывают массив, номер записи и поле.
Менеджеру доступен просмотр настроек модели: ползунки и поля отключены,
добавление признаков, сохранение, загрузка снимка и управление менеджерами скрыты.
Прямой переход менеджера к управлению пользователями возвращает на дашборд.
Права запросов дополнительно проверяет бэкенд.

Ошибки 401 после отказа refresh переводят на вход; 403 показывает недостаток прав,
429 — понятное сообщение о лимите. Сетевая ошибка позволяет повторить операцию.
Подпись о живых обновлениях показывается после подключения потока; при обрыве
виден статус восстановления соединения. Пустые списки и загрузка обозначены явно.

В настройках восстановлена форма с ползунками весов, числовыми порогами,
добавлением признака и полем даты расчёта. Данные загружаются и сохраняются
через API; PATCH передаёт только изменённые параметры, остальные настройки
сохраняются. Пока заглушка бэкенда возвращает только `{"asOf": null}`, форма
использует исходные значения макета и показывает, что веса и пороги пока
не применяются к оценкам. API сводки не содержит истории
по дням, а причины не содержат процентных вкладов: интерфейс показывает
актуальное распределение риска и тексты причин. Вместо вымышленной активности
карточка показывает сводку транзакций и время расчёта.

Проверки из `frontend`:

```powershell
npm.cmd run build
npm.cmd run lint
npx.cmd playwright test
```

CI фронтенда находится в `.github/workflows/frontend.yml`: Node.js 22,
`npm ci`, lint и production-сборка при PR и push в ветки
`main`, `develope`, `develop`. Бэкенд проверяется отдельным существующим workflow.

Браузерные тесты перехватывают API на уровне HTTP и подменяют EventSource
для проверки событий и восстановления сессии. Работающий бэкенд для них
не требуется; для проверки реального SSE и cookie нужен запущенный бэкенд.
